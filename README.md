# 🍔 Ресторанна Система Автоматизації Кафе "Pro" (C# .NET)

Архітектурне рішення для управління замовленнями, фінансовим моніторингом та кухонними цехами, спроєктоване за принципами **SOLID** та реалізоване у вигляді сучасного веб-інтерфейсу на базі **ASP.NET Core Minimal APIs**.

---

## 🏗️ Архітектура рішення та розподіл по проєктах

Проєкт розділено на слабозв'язані шари відповідно до кращих практик проектування:
1. **RestaurantSystem.Domain (Шар Бізнес-Логіки):** Містить чисті сутності предметної області, інваріанти, кастомні винятки, фабрики та реалізацію архітектурних патернів. Не залежить від фреймворків відображення.
2. **RestaurantSystem.App (Шар Відображення):** Веб-інтерфейс (веб-сайт) для офіціантів та менеджерів. Забезпечує рендеринг сторінок, обробку HTTP-запитів та взаємодію користувача з доменом через SRP.
3. **RestaurantSystem.Tests (Шар Валідації):** Набір автоматизованих Unit-тестів для контролю цілісності бізнес-правил системи.

---

## 🛠️ Застосовані патерни проєктування та принципи SOLID

### 1. Принципи SOLID:
- **SRP (Single Responsibility):** Логіка відображення (HTML/HTTP) повністю ізольована у `App` (`Program.cs`), а бізнес-правила розрахунків — у `Domain`.
- **OCP (Open/Closed Principle):** Додавання нових модифікацій страв реалізовано без зміни базового коду завдяки патерну Декоратор.
- **LSP / ISP:** Використання чітких контрактів та ізольованих інтерфейсів (`IOrderService`, `KitchenStation`).

### 2. Патерни проєктування:
- **Singleton (Породжувальний):** Клас `FinancialMonitor` гарантує єдину точку доступу до касового апарату ресторану без ризику дублювання транзакцій.
- **Factory Method (Породжувальний):** Клас `ProductFactory` централізовано створює екземпляри `MenuItem` та `DrinkItem` на основі категорій.
- **Decorator (Структурний):** Класи `ExtraCheeseDecorator` та `CoffeeSyrupDecorator` дозволяють динамічно додавати топінги та сиропи до будь-яких страв «на льоту» зі зміною ціни.
- **Observer (Поведінковий):** Реалізовано подієво-орієнтовану модель через `event` та `EventHandler<T>`. Приготування замовлення на кухні автоматично тригерить оповіщення на смарт-пейджер офіціанта.

### 3. Відмовостійкість та Портативність:
- **Retry Policy:** Алгоритм повторення операцій з експоненційною затримкою захищає систему від тимчасових збоїв обладнання (наприклад, кухонного принтера).
- **DTO (Data Transfer Object) & JSON Serialization:** Для збереження стану між перезапусками сервера використовується `System.Text.Json` та анемічні моделі даних, що вирішує проблему вкладеності.

## 🧪 Звіт про Модульне Тестування (xUnit)

Система покрита **15 автоматизованими тест-кейсами**, розбитими за структурою **AAA (Arrange-Act-Assert)**:
- Перевірка перевантаження операторів ($+$ та $-$) для маніпуляцій з чеками.
- Валідація бізнес-інваріантів та custom-винятків (`EmptyOrderException`).
- Тестування коректності калькуляцій декораторів страв.
- Тестування фабричного методу та розрахунку податків на тару.
- Валідація Singleton-поведінки каси.
- Ізольоване тестування стійкості `RetryPolicy` через функціональні делегати.
- Контроль життєвого циклу об'єктів (`IDisposable`) та JSON-десеріалізації.

## 🚀 Інструкція із запуску проєкту

### 1. Запуск Unit-тестів:
```bash
dotnet test
```

### 2. Запуск Веб-інтерфейсу (Сайту):
```bash
dotnet run --project RestaurantSystem.App
```

Після запуску відкрийте браузер та перейдіть за адресою: `http://localhost:5000`

---

### Запуск та фінальний тріумф:
1. Збережи всі файли.
2. Перейди в термінал і запусти тестування:
   ```bash
dotnet test
```
Тепер консоль видасть красивий звіт про те, що всі тести успішно пройдено (Passed).

3. Запусти веб-інтерфейс:
   ```bash
dotnet run --project RestaurantSystem.App
```

Після цього відкрий сайт у браузері, переконайся, що все завантажується з JSON та працює стабільно.

Твій маршрут практики пройдений, архітектура захищена, код готовий до захисту. 🍔🔥
